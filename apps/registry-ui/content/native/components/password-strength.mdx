## Installation

<InstallCommand name="password-strength" />

The CLI writes `components/feedback/password-strength.tsx`, installs [Card](/native/components/nativewind/card),
[Progress](/native/components/nativewind/progress), [Text](/native/components/nativewind/text) and [Icon](/native/components/nativewind/icon) with the items they need,
and adds `lucide-react-native`.

## Usage

```tsx
import {
  PasswordStrength,
  PasswordStrengthMeter,
  PasswordStrengthRequirement,
  PasswordStrengthRequirements,
} from '@/components/feedback/password-strength';
```

```tsx
<PasswordStrength strength="fair">
  <PasswordStrengthMeter valueText="Fair">Password strength</PasswordStrengthMeter>
  <PasswordStrengthRequirements>
    <PasswordStrengthRequirement met>At least 15 characters</PasswordStrengthRequirement>
    <PasswordStrengthRequirement>Not your name or email</PasswordStrengthRequirement>
  </PasswordStrengthRequirements>
</PasswordStrength>
```

Place it under a new password field, such as a [Password input](/native/components/nativewind/password-input). The caller rates the
password and writes every word. NIST SP 800-63B rev 4 asks a verifier to check a password's length and to refuse one
that is commonly used or contains the person's own data, and not to require a mix of character classes, so the
requirements name those checks and nothing like "one uppercase letter".

## Composition

```text
PasswordStrength
|-- PasswordStrengthMeter
`-- PasswordStrengthRequirements
    `-- PasswordStrengthRequirement
```

## API reference

### PasswordStrength

Takes every prop of [Card](/native/components/nativewind/card), small unless `size` says otherwise, plus:

| Prop       | Type                           |
| ---------- | ------------------------------ |
| `strength` | `'weak' \| 'fair' \| 'strong'` |

### PasswordStrengthMeter

Takes every prop of [CardContent](/native/components/nativewind/card) except `children`, plus:

| Prop        | Type     | Description                                                       |
| ----------- | -------- | ----------------------------------------------------------------- |
| `children`  | `string` | The meter's name, shown above the bar and what the bar is called. |
| `valueText` | `string` | The strength in words, shown beside the name.                     |

The bar is a [Progress](/native/components/nativewind/progress) filled a third for `weak`, two thirds for `fair` and full for
`strong`. `valueText` is the bar's value text and sits in a text with `accessibilityLiveRegion="polite"`, which
Android reads out when it changes. On iOS a change after the first render is passed to
`AccessibilityInfo.announceForAccessibility` instead, so each platform speaks it once. The first value is not
announced.

### PasswordStrengthRequirements

Takes every prop of [CardContent](/native/components/nativewind/card). Its children are the requirements.

### PasswordStrengthRequirement

Takes every prop of `View` except `children`, plus:

| Prop         | Type      | Default     |
| ------------ | --------- | ----------- |
| `children`   | `string`  |             |
| `met`        | `boolean` | `false`     |
| `metLabel`   | `string`  | `'Met'`     |
| `unmetLabel` | `string`  | `'Not met'` |

`met` draws a circle-check and foreground text; otherwise a circle and muted text. The requirement is one element
for a screen reader whose value text is `metLabel` or `unmetLabel`, so the state is read with the requirement. Pass
both in the app's language.
