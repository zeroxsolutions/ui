`@zeroxsolutions/icons` is an npm package, not a registry item. The AI Provider Picker block depends on it, and an
app can import from it directly.

<ComponentPreview name="icons-demo" />

## Installation

```bash
pnpm add @zeroxsolutions/icons react react-dom
```

`react` and `react-dom` are peer dependencies, on React 19.

## Usage

Brand marks come from one component; file-type icons have one import path each.

```tsx
import { BrandMark } from '@zeroxsolutions/icons/brand-mark';
import { TypescriptIcon } from '@zeroxsolutions/icons/material/typescript';
```

```tsx
<BrandMark name="facebook" />
<BrandMark name="openai" variant="mono" size={24} label="OpenAI" />
<BrandMark name="claude" variant="avatar" size={32} />
<TypescriptIcon size="1.5rem" />
```

## Categories

### brand-mark

`<BrandMark name="...">` draws any of about 200 brands: AI labs and inference hosts, developer and cloud
tools, social networks and workspace apps.

- `name` is a union generated from the manifest, so a mistyped name does not compile.
- `variant` is `'color'`, `'mono'`, `'avatar'` or `'combine'`, and defaults to `'color'`.
- `size` is a number of pixels or a CSS length, `'1em'` by default; the mark keeps its aspect ratio.
- `label` gives the mark an accessible name. Without it the mark is decorative, since in a button or a link
  the text beside it is the name.
- `shape` is `'circle'` or `'square'` and rounds an `avatar`.
- `base` serves one call from another origin.

How each variant draws:

| Variant   | Element                                                                                                                  |
| --------- | ------------------------------------------------------------------------------------------------------------------------ |
| `color`   | an `<img>` of `<base>/color/<name>.svg`                                                                                  |
| `mono`    | a `<span>` whose `mask-image` is `<base>/mono/<name>.svg` over `currentColor`, so it takes the text colour and the theme |
| `avatar`  | an `<img>` of `<base>/avatar/<name>.svg`, rounded per `shape`                                                            |
| `combine` | a masked `<span>`: the mark beside its wordmark, drawn as `mono` is                                                      |

`BrandMarkStyleProvider` makes the variant ambient for every `BrandMark` below it, and a call's own `variant`
wins. `useBrandMarkStyle()` reads and sets it. A `BrandMark` outside any provider reads the module default;
outside React, `setBrandMarkStyle(variant)` sets that default and `brandMarkUrl(name, { variant, base })`
returns a file's URL.

A variant a brand lacks is resolved before any request: `combine` and `avatar` fall to `color`, and `color`
falls to `mono`. A file that fails to load falls the same way, and when `mono` fails the mark renders the first
letter of its name in a round `<span>`, so nothing is blank.

Every file is read from `https://icons.zeroxsolutions.com/brands`. To serve them yourself, copy
`dist/assets/brands` from the package to your own origin and point the module at it:

```tsx
import { BrandMark, setBrandMarkBase } from '@zeroxsolutions/icons/brand-mark';

setBrandMarkBase('/vendor/brands'); // module-wide; `base` on one call wins over it
<BrandMark name="slack" base="https://cdn.example.com/brands" />;
```

Call `setBrandMarkBase` in a module both the server and the client evaluate, or pass `base`: a base set
on one side alone gives a server-rendered `src` the client's does not match. A base on another origin
must answer with `Access-Control-Allow-Origin`, since `mono` and `combine` are fetched in CORS mode.

### material

The Material Icon Theme's file-type icons, in full colour. The export is the name in PascalCase plus `Icon`, so
`material/typescript` exports `TypescriptIcon`. An icon with artwork for a light background also exports it as
`.Light`.
