## Usage

```tsx
import type { DocJSON } from '@zeroxsolutions/editor-core/document/core/index';

import { section } from '@/components/editor/document/features/section';
import { standardKit } from '@/components/editor/document/features/standard';
import { Editor } from '@/components/editor/document/react';
```

```tsx
const features = [standardKit(), section()];

function PageEditor({ content }: { content: DocJSON }) {
  return <Editor features={features} content={content} />;
}
```

`section` adds the `section` block, which holds any block but another section, columns and cards among them, and
sits only at the top of the document: a page is a run of sections and blocks. Its slash item is "Section", which
runs the standard kit's `insertSection`: it adds one holding an empty line after the block holding the caret, and
the slash menu does not offer it inside a section, a column, a callout, a toggle, a quote, a list or a table. A
section pasted or dropped there lands at the top.

Its floating toolbar sets its background, its padding and its width, through the standard kit's `setSectionLayout`.
The background is `none`, `muted`, `primary`, `accent` or one of the eight hues, drawn from the theme's tokens so it
follows light and dark mode; the padding is `none`, `small`, `medium` (the default) or `large`; the width is
`content` (the default), `wide` or `full`. A wide or a full section reaches into the room the surface leaves beside
the text, `--section-bleed`, which the Document Editor's styles set to the editable editor's gutter; the Viewer has
none unless its host sets one. A full width image, video, embed or card in a section stops at the section's
padding, whatever the section's width. [Editor Layout](/docs/editor/editor-layout) shows a section with the other
blocks' layout.

`messages` takes the toolbar's words, `LayoutWords`, and `widths` narrows the widths it offers: the email editor's
section offers `content` and `wide`. HTML keeps the section whole; Markdown has no section, so it writes its blocks
in order.

The `Viewer` draws the same block, with the same feature in its `features`, wherever a stored document is only read.
