## Usage

```tsx
import { emailProfile, type EditorEmailBlock } from '@zeroxsolutions/editor-core/profiles/index';
import { createEmailRenderer } from '@zeroxsolutions/editor-core/template/email/index';

import { EmailEditor } from '@/components/editor/profiles/email/email-editor';
```

```tsx
const profile = emailProfile({
  variables: [
    { name: 'first_name', type: 'string', label: 'first name', sampleValue: 'Lan' },
    { name: 'account_url', type: 'url', label: 'account link', sampleValue: 'https://example.com/account' },
  ],
});
const renderer = createEmailRenderer({ theme });

function WelcomeEmail({ blocks, save }: { blocks: EditorEmailBlock[]; save: (blocks: EditorEmailBlock[]) => void }) {
  return (
    <EmailEditor
      label="Email body"
      profile={profile}
      value={blocks}
      onChange={save}
      renderer={renderer}
      previewInput={{ subject: 'Welcome', preheader: null, locale: 'en', layoutProps }}
    />
  );
}
```

The editor offers the Document Editor's paragraph, bulleted list, callout, code block and divider, and the
email's button, columns and HTML blocks. Click a block's grip, or press Mod-/, to open its block menu. The
menu holds Turn into, Duplicate and Delete, and the block's Align, Space after, Tone, Width, Lanes or Link.

With a `renderer`, the preview shows the rendered email with each variable's `sampleValue`. `theme` is the
renderer's `EmailTheme` and `layoutProps` its logo and footer, and the demo's source defines both.

Hand the blocks `onChange` gives you back as `value`, and the editor does not reload them. After a save,
call `editor.run('assignBlockIds', { ids })` on the editor `onReady` gave you, with a map of block key to
saved id. The blocks it reports from then on carry those ids.

## API reference

### EmailEditor

| Prop                   | Type                                             | Default  | Description                                                                                                                                      |
| ---------------------- | ------------------------------------------------ | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `profile`              | `EditorProfile`                                  | -        | The blocks and variables the author may use, from `emailProfile`.                                                                                |
| `value`                | `EditorEmailBlock[]`                             | -        | The blocks shown. A value that differs from the last `onChange` loads in its place.                                                              |
| `label`                | `string`                                         | -        | The accessible name of the editable area.                                                                                                        |
| `renderer`             | `EmailPreviewRenderer`                           | -        | A `createEmailRenderer` instance. Without one, the editor draws no preview.                                                                      |
| `previewInput`         | `EmailPreviewInput`                              | -        | The subject, preheader, locale and layout props the preview renders with.                                                                        |
| `layout`               | `'auto' \| 'split' \| 'tabs'`                    | `'auto'` | `split` draws the preview beside the editor, `tabs` under a Preview tab, and `auto` splits at a viewport 768px wide or more and uses tabs below. |
| `messages`             | `Partial<ProfileEditorMessages>`                 | -        | Your words for the strings the editor draws. A key left out stays English.                                                                       |
| `readOnly`             | `boolean`                                        | `false`  | Shows the blocks and their problems with no toolbar or menus.                                                                                    |
| `required`             | `readonly string[]`                              | -        | The ids of the blocks the author may not delete.                                                                                                 |
| `structure`            | `'free' \| 'locked'`                             | `'free'` | `locked` allows edits to text, marks (bold, italic, link) and variables only.                                                                    |
| `features`             | `EditorFeature[]`                                | -        | Your own blocks, each with an email codec. Read once, on mount.                                                                                  |
| `className`            | `string`                                         | -        | Classes for the frame.                                                                                                                           |
| `onChange`             | `(blocks: EditorEmailBlock[]) => void`           | -        | Called with the blocks after each edit.                                                                                                          |
| `onBlur`               | `() => void`                                     | -        | Called when the focus leaves the editor and the menus it opened.                                                                                 |
| `onValidate`           | `(problems: ProfileProblem[]) => void`           | -        | Called with the problems on mount and when they change.                                                                                          |
| `renderBlockAdornment` | `(id: string \| null, key: string) => ReactNode` | -        | Draws your content beside each block. `id` is null until the block is saved.                                                                     |
| `onReady`              | `(editor: IEditor) => void`                      | -        | Called once with the editor.                                                                                                                     |

Build `messages` once per locale; a new object rebuilds the toolbar and the menus. Its English defaults are
`DEFAULT_PROFILE_MESSAGES` in `messages.ts`.

### emailProfile

| Option       | Type                    | Default         |
| ------------ | ----------------------- | --------------- |
| `allow`      | `EmailBlockKind[]`      | all eight       |
| `variables`  | `VariableDeclaration[]` | `[]`            |
| `bounds`     | `Partial<EmailBounds>`  | the table below |
| `extraKinds` | `string[]`              | `[]`            |

`extraKinds` names the kinds of your own `features`. The renderer caps `text`, `label`, `href`, `listItems`
and `lanes` at their defaults, and a higher value throws `editor.profile.bound_above_renderer`. `blocks` and
`variables` may be raised.

| Bound       | Default | Limits                                          |
| ----------- | ------- | ----------------------------------------------- |
| `text`      | 5000    | characters of a paragraph, callout or list item |
| `label`     | 200     | characters of a button's label                  |
| `href`      | 2000    | characters of a button's link                   |
| `listItems` | 20      | items of a list                                 |
| `blocks`    | 50      | blocks in all, a lane's blocks included         |
| `lanes`     | 4       | lanes of a columns block                        |
| `variables` | 20      | declared variables                              |

## Variables

A variable has a `name` of word characters, a `type` of `string`, `duration`, `url` or `email`, and an
optional `label`, `sampleValue` and `required`. Type `{{` or use the toolbar's variable menu to insert one.
The toolbar's link picker links the selected text to a `url` variable, and a button's link is set from its
block menu. A `required` variable that no block uses is a problem.

To change the variables, pass a new profile. If you change the declarations in place instead, call
`refreshVariables(editor)` from `variables/variable.tsx`.

## Validation

Each problem is marked on its block, with its message on hover and focus. A problem with no block, such as
`required-variable-not-printed` or `too-many-blocks`, and each problem the preview's render reports are listed
in the editor's footer. F8 and Shift+F8 move to the next and previous problem, and Escape on a marker returns
to its block.

On the server, `validate(blocks, profile)` from `@zeroxsolutions/editor-core/profiles/index` returns the same
list for the same profile, except `block-not-carried`. Only the editor reports that one, since it reads the
document before the export.

| Kind                            | Message                                     |
| ------------------------------- | ------------------------------------------- |
| `variable-undeclared`           | This variable is not declared               |
| `href-not-url-variable`         | The link must be one link variable          |
| `link-not-url-variable`         | A link can only point to a link variable    |
| `required-variable-not-printed` | A required variable is not used             |
| `markup-malformed`              | The formatting is not closed                |
| `block-not-allowed`             | This block is not allowed here              |
| `unknown-block-type`            | This block is of an unknown type            |
| `block-nested-too-deep`         | Columns cannot hold columns                 |
| `lanes-mismatch`                | The columns do not match their widths       |
| `text-empty`                    | This block is empty                         |
| `text-too-long`                 | This text is too long                       |
| `list-too-long`                 | This list has too many items                |
| `too-many-blocks`               | The email has too many blocks               |
| `block-not-carried`             | The email keeps only the text of this block |

`block-not-carried` marks a block the email cannot hold, such as a pasted heading or numbered list.

## Markup

A paragraph, a callout and a list item store their text in this markup:

| Write                  | Reads as                            |
| ---------------------- | ----------------------------------- |
| `**bold**`             | bold                                |
| `_italic_`             | italic                              |
| `[label]({{name}})`    | a link to the `url` variable `name` |
| `\*`, `\_`, `\[`, `\\` | the character itself                |
