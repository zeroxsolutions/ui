## Usage

```tsx
import type { DocJSON } from '@zeroxsolutions/editor-core/document/core/index';

import { file } from '@/components/editor/document/features/file';
import { standardKit } from '@/components/editor/document/features/standard';
import { Editor } from '@/components/editor/document/react';
```

```tsx
const features = [standardKit(), file()];

function NotesEditor({ content }: { content: DocJSON }) {
  return <Editor features={features} content={content} />;
}
```

`file` adds the `file` block: a file to download, drawn as a row with its icon, name and size, the whole row a
link. Its slash item is "File". The author pastes the file's link into the empty block, and its name is read from
the last part of the address. `size` is the file's size in bytes, from 0 to 2^31. Give `file` your upload and the
empty block gets an Upload tab beside its link, and a file pasted or dropped into the editor that no other block
takes becomes a file block; the file's name and size fill the block's once your address lands:

```tsx
const features = [standardKit(), file({ upload, maxBytes: 50 * 1024 * 1024 })];
```

[Editor Uploads](/docs/editor/editor-uploads) describes the upload. A file stored by other means is inserted with
the `insertBlock:file` command, which takes the block's fields and attributes in `attributes`:

```tsx
editor.run('insertBlock:file', {
  attributes: { name: 'itinerary.pdf', href: 'https://files.example.com/itinerary.pdf', size: 482133 },
});
```

HTML writes the file as a `download` link with its name and size. Markdown writes the same HTML on one line.

The `Viewer` draws the same block, with the same feature in its `features`, wherever a stored document is only read.
