## Usage

```tsx
import { smsProfile } from '@zeroxsolutions/editor-core/profiles/index';

import { SmsEditor } from '@/components/editor/profiles/sms/sms-editor';
```

```tsx
const profile = smsProfile({ variables: [{ name: 'code', type: 'string', label: 'code', sampleValue: '482913' }] });

function SignInMessage({ body, save }: { body: string; save: (body: string) => void }) {
  return <SmsEditor label="Message" profile={profile} value={body} onChange={save} />;
}
```

The body is plain text and `{{name}}` variables, drawn in the Email Editor's frame with the variable menu in
its toolbar. The meter in the footer shows the body's length against one segment's limit in its encoding, GSM-7
or UCS-2, counting each variable as its `{{name}}` text. When the body needs more than `maxSegments`
segments, the meter and the text past the limit are marked.

## API reference

### SmsEditor

| Prop         | Type                                   | Default | Description                                                                       |
| ------------ | -------------------------------------- | ------- | --------------------------------------------------------------------------------- |
| `profile`    | `EditorProfile`                        | -       | The variables and the segment limit, from `smsProfile`.                           |
| `value`      | `string`                               | -       | The body shown. A value that differs from the last `onChange` loads in its place. |
| `label`      | `string`                               | -       | The accessible name of the editable area.                                         |
| `messages`   | `Partial<ProfileEditorMessages>`       | -       | Your words for the strings it draws, `smsMeter` among them.                       |
| `readOnly`   | `boolean`                              | `false` | Shows the body, its problems and its cost with no variable menu.                  |
| `className`  | `string`                               | -       | Classes for the frame.                                                            |
| `onChange`   | `(body: string) => void`               | -       | Called with the body after each edit.                                             |
| `onBlur`     | `() => void`                           | -       | Called when the focus leaves the editor and the menus it opened.                  |
| `onValidate` | `(problems: ProfileProblem[]) => void` | -       | Called with the problems on mount and when they change.                           |
| `onReady`    | `(editor: IEditor) => void`            | -       | Called once with the editor.                                                      |

`smsMeter` takes `units`, `limit`, `encoding` (`gsm7` or `ucs2`), `segments` and `maxSegments`, and returns
the meter's text.

### smsProfile

| Option        | Type                    | Default |
| ------------- | ----------------------- | ------- |
| `variables`   | `VariableDeclaration[]` | `[]`    |
| `maxSegments` | `number`                | `1`     |

## Variables

Variables are declared as in the [Email Editor](/docs/editor/email-editor#variables). Type `{{` or use the
toolbar's variable menu to insert one.

## Validation

F8 and Shift+F8 move to the next and previous problem, and Escape on a marker returns to the text. On the
server, `validate(body, profile)` from `@zeroxsolutions/editor-core/profiles/index` returns the same list.

| Kind                            | Message                            |
| ------------------------------- | ---------------------------------- |
| `variable-undeclared`           | This variable is not declared      |
| `required-variable-not-printed` | A required variable is not used    |
| `sms-segment-exceeded`          | The message is longer than allowed |
| `sms-placeholder-malformed`     | A variable is not closed           |

## Markup

The body has no formatting. `**`, `_` and `[label](...)` stay as typed. Enter and a pasted line break make a
new line.
