## Blocks

Each block below works in the editors it names. A Document Editor block is a feature you add to `features`,
installed from its page. The [Email Editor](/docs/editor/email-editor) holds each of its blocks already, and a
profile's `allow` picks the ones a mail may hold.

card and, through [Editor Card](/docs/editor/editor-card), the document's.

a preset, as [Block Presets](/docs/editor/block-presets) shows.

## Your own block

`defineBlock` from `@zeroxsolutions/editor-core/blocks/index` declares a block once, with its fields and
attributes, a `document` side for the Document Editor, an `email` side for the email editor, or both.
`blockFeature` turns a definition with a document side into a Document Editor feature. It builds the node, the
slash item, the block menu's settings and the HTML and Markdown codecs from the definition, and draws the block
with your `view` in the editor and the `Viewer` alike.

```tsx
import type { ReactNode } from 'react';

import { defineBlock } from '@zeroxsolutions/editor-core/blocks/index';
import { link, plainText } from '@zeroxsolutions/editor-core/template/email/index';

import { blockFeature, type BlockViewPropsOf } from '@/components/editor/document/blocks';
```

```tsx
const place = defineBlock({
  type: 'place',
  label: 'Place',
  description: 'A place to visit',
  fields: { name: plainText({ required: true }), map: link() },
  document: {
    html: ({ fields }, markup) => markup`<p data-place><a href="${markup.url(fields.map)}">${fields.name}</a></p>`,
  },
});

function PlaceView({ fields, editable, update }: BlockViewPropsOf<typeof place>): ReactNode {
  return editable ? (
    <input value={fields.name} placeholder="Place" onChange={(event) => update({ name: event.currentTarget.value })} />
  ) : (
    <p>{fields.name}</p>
  );
}

const placeFeature = blockFeature(place, { view: PlaceView });
```

`markup` escapes every value it is handed. A value goes in text or in a quoted attribute that holds no address,
and an address goes through `markup.url` as the whole of an `href`, a `src` or a `poster`: `href` takes a web or
mail address, `src` and `poster` a web one, and any other address leaves the attribute out. `defineBlock` throws
`BlockDefinitionInvalid` for a definition that breaks these rules, and for a type a Document Editor node or a
library block already takes. HTML carries the block's fields in `data-block-attrs`, and Markdown writes the same
HTML on one line, so the block reads back whole from either.

A block with an `email` side goes in `emailProfile({ blocks })`, in the email editor's `blocks` and in
`createEmailRenderer`'s `extraBlocks`, as [Email Editor](/docs/editor/email-editor#your-own-blocks) shows.
