# zui zones Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Split the registry site into a web zone (`apps/registry-ui`) and a native zone
(`apps/registry-native-ui-docs-zone`) on `ui.zeroxsolutions.com`, each built from its own pages package
and deployed only when a change reaches it.

**Architecture:** Three stacked PRs. PR 1 moves the web registry and the site components into
`packages/ui` and each platform's pages into `packages/ui-docs-web` and `packages/native-ui-docs-web`,
with `registry-ui` still serving everything. PR 2 adds the native zone, its Cloudflare routes and the
affected deploy, while `registry-ui` keeps its native pages as the fallback. PR 3 removes the native
side from `registry-ui`.

**Tech Stack:** Next.js 16 on OpenNext Cloudflare, fumadocs-mdx/core, nx 23 with inferred targets,
oxlint with `@nx/oxlint/boundaries-plugin`, vitest, Playwright, GitHub Actions on hosted runners.

**Spec:** `docs/superpowers/specs/2026-11-03-zui-zones-design.md`

## Global Constraints

- Project names: `packages/ui` (`@zeroxsolutions/ui`), `packages/ui-docs-web` (`@zeroxsolutions/ui-docs-web`),
  `packages/native-ui-docs-web` (`@zeroxsolutions/native-ui-docs-web`), `apps/registry-native-ui-docs-zone`,
  `apps/registry-native-ui-docs-zone-e2e`; worker `ui-sdk-registry-native-ui-docs-zone`.
- Tags: `type:ui` on `packages/ui` and `packages/native-ui`; `type:context-frontend` + `context:ui-docs`
  on `ui-docs-web`; `type:context-frontend` + `context:native-ui-docs` on `native-ui-docs-web`.
- Projects are created with nx generators (dry run first, read the file list); targets inferred, only
  the `nx:run-commands` targets that exist today move or are copied.
- A context package imports nothing from `next/*`; the other context's package is imported by nobody
  but its own zone app, not even its `routes` subpath.
- Native zone routes: `/native`, `/native/*`, `/native-preview/*`, `/native-preview-uniwind/*`,
  `/og/native/*`, `/llms.mdx/native/*`, `/native-static/*`, `/r/styles/nativewind-*`,
  `/r/styles/uniwind-*`. Asset prefix `/native-static`.
- `public/r` is byte-identical before and after every task (`diff -r` empty).
- Never run `nx affected` or a broad `run-many` locally; single-target `pnpm nx <target> <project>` only.
  Push and let the pre-push hook and CI gate.
- Commits: message in a file, `git commit -F`, subject at most 72 characters, ending with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; `git add` names paths; no hook skipped;
  never stage `apps/registry-ui/next-env.d.ts` or `apps/native-preview-uniwind/uniwind-types.d.ts`.
- PR bodies end with `🤖 Generated with [Claude Code](https://claude.com/claude-code)`. Merge and the
  production push (`git push origin master:production`) only when the user asks.

## Review Focus

1. A client-side navigation from a web page into `/native` (or back) after the routes exist: Next's
   router fetches `/native?_rsc=...` and the edge hands it to the other zone. Every cross-zone link is a
   plain `<a>` from PR 2 on (Task 9's spec).
2. A native zone asset outside `/native-static`: fonts and CSS under `_next/static/media` left at the
   root 404 behind the edge. Task 8's build asserts nothing is left at `.open-next/assets/_next`, and
   Task 9's e2e fails on any failed request.
3. A published registry file changing as items move: `shadcn add` users get different files. Task 2
   and Task 13 diff `public/r` against the baseline.
4. A failed native deploy followed by a web-only push: the native change never ships. Task 11's spec
   for the base resolver.
5. Theme or remembered style lost across the switch: both zones must use the same `next-themes`
   storage key and `use-remembered-choice` keys. Task 8 reuses the provider from `packages/ui`; Task 12's
   post-deploy check toggles dark on `/docs` and opens `/native`.
